# Physical Neural Network Hardware-Noise Modeling — Tiered Reference

## How to use this skill (for the rewriter agent)

1. You will normally implement one tier per session. The previous Chia node indicates which tier you were
   asked for (0-5), then read **only** that block plus the two
   shared sections "Vocabulary" and "ONN-specific noise channels". Your role doesn't include 
   evaluation since its responsibility lies with another agent. You may be requested to correct your rewrite if the evaluation performed externally presents errors; usually you'll receive hints.
2. Each tier block is designed to be enough to implement without external reading.
   The `Links` line in each block is a fallback for when you need exact equations,
   measured coefficients, or API signatures.
3. Do not silently upgrade or downgrade the requested tier. If you believe another
   tier is more appropriate, implement the requested one and note the suggestion in the database.
4. The changes are written in PyTorch and are registered systematically in the Un-0 repo with the given tools and instructions. 
5. Context assumed: weights/couplings were trained in floating point on GPU; you
   are simulating **inference** on analog hardware.

## Vocabulary (shared, read once)

- **Static mismatch**: fixed once per fabricated/programmed device instance
  (fabrication variation, programming/write error). Same for every input.
- **Run-to-run variation**: changes when the device is reprogrammed or restarted.
- **Dynamic / read noise**: changes within or between inference reads (1/f, RTN,
  thermal, phase diffusion). Redrawn per read / per timestep.
- **Drift / relaxation / aging**: slow evolution over seconds-hours-cycles-temp.
- **Interface error**: DAC/ADC quantization, clipping, saturation, gain/offset,
  readout/phase-detector precision.
- **Model-form error**: mismatch between the digital twin and physical dynamics;
  cannot be removed by adding noise — only by better physics or calibration.

Key framing from the Momeni et al. review: a digital twin is a physics-based model
and/or NN standing in for the real device; an in-silico-trained PNN risks accuracy
loss on transfer because the twin may miss fabrication imperfections, misalignments
and detection noise. Discretizing the physical world finer improves accuracy but
raises cost fast — this is exactly the fidelity/cost trade-off the tiers span.
Review: https://arxiv.org/abs/2406.03372 (Nature 2025, doi:10.1038/s41586-025-09384-2)

## Tier 0 — Static deterministic perturbation on weights/couplings

**Concept.** When FP-trained weights are written to analog devices each acquires a
fixed programming/quantization error. Model it as one frozen per-weight offset,
held constant across every input and timestep. Physically grounded: programming
error on memristive synapses is often ~1-10% of the target conductance.

**Implementation recipe.**

Requires implementation to PyTorch; don't use NumPy. 
```python
import numpy as np
rng = np.random.default_rng(0)          # fix seed => one frozen device instance
# absolute:  delta = sigma_abs * z
# relative:  delta = sigma_rel * |W| * z    (write error scales with magnitude)
delta = sigma_rel * np.abs(W) * rng.standard_normal(W.shape)
W_hw = W + delta                        # reuse W_hw for the WHOLE test set
```
Sweep `sigma_rel` over e.g. {0.01, 0.02, 0.05, 0.1}. Also try a deliberate bias
(`+mu`) and a bounded-uniform variant. For ONNs apply the same idea to coupling
`K[i,j]` (and separately to per-oscillator frequency, see ONN block).

**Calibration defaults.** 1-10% relative is the standard memristive programming-
error band; start at 2%.

**Cost.** One forward pass over the test set per (sigma, seed). Negligible.

**Limitations.** Deterministic and write-time only; captures no temporal noise,
drift, correlation, or readout quantization. Never report a single seed — average
over several frozen instances.

Links: Joshi et al. (δG 1-10%), doi:10.1038/s41467-020-16108-9 ;
aihwkit programming-noise concept: https://aihwkit.readthedocs.io/en/latest/pcm_inference.html

## Tier 1 — Independent stochastic parameter noise (i.i.d. Gaussian)

**Concept.** Model limited analog SNR as zero-mean i.i.d. noise added to weights,
RESAMPLED at a declared timescale. Estimate expected accuracy by Monte Carlo.

**Implementation recipe.**

Requires implementation to PyTorch; don't use NumPy. 

```python
# additive:        W_t = W + eta * z
# multiplicative:  W_t = W * (1 + eta * z)   (SNR proportional to magnitude)
def noisy_forward(model, x, W, eta, n=100, rng=None):
    rng = rng or np.random.default_rng()
    outs = []
    for _ in range(n):                              # redraw per forward pass
        W_t = W + eta * rng.standard_normal(W.shape)
        outs.append(model.forward_with(W_t, x))
    return np.mean(outs, axis=0), np.std(outs, axis=0)
```
CRITICAL: declare the redraw timescale — per deployment / per batch / per sample /
per oscillation cycle / per integration step. It changes results and must appear
in the report. ~100 draws is a common default for expected output.

**Calibration defaults.** Sweep eta as a fraction of the weight std; report the
accuracy-vs-eta curve rather than one point.

**Cost.** n x (Tier-0 cost). Linear in number of Monte Carlo draws.

**Limitations.** Ignores where noise physically enters (see Tier 2), correlations,
drift, and readout quantization. i.i.d. Gaussian is a baseline, not physics.

Links: Zhou et al. "Noisy Machines", https://arxiv.org/abs/2001.04974

## Tier 2 — Placement-aware block + interface model

**Concept.** WHERE noise enters matters more than its exact shape. Empirically,
nonidealities that add noise to inputs/outputs (activations) can hurt accuracy
more than weight noise. Add DAC/ADC quantization and clipping at the true
interfaces. Generic form:
`y_hw = Q_out( F_hw( Q_in(x), W_hw ) + eps_out )`.

**Implementation recipe.**

Requires implementation to PyTorch; don't use NumPy. 

```python
def quantize(x, n_bits, x_max):                 # uniform mid-tread quantizer
    lsb = (2*x_max) / (2**n_bits - 1)
    return np.clip(np.round(x/lsb)*lsb, -x_max, x_max)

x_q   = quantize(x, n_bits=7, x_max=x_absmax)               # input DAC
y_lin = F(x_q, W_hw)                                         # W_hw from Tier 0/1
y     = quantize(y_lin + out_noise*rng.standard_normal(y_lin.shape),
                 n_bits=8, x_max=y_absmax)                   # output + ADC
```
Add, at their locations: coupling/programming error, oscillator freq mismatch,
phase/timing jitter, amplitude noise, offsets, gain error, saturation. Keep ADC
full-scale (`x_max`) consistent across layers — it reflects fixed converter range.
aihwkit exposes these directly (`forward.inp_res`, `forward.out_res`,
`w_noise_type=ADDITIVE_CONSTANT`, `w_noise`, `out_noise`).

**Calibration defaults.** Typical starting points from aihwkit examples: 7-bit DAC,
8-bit ADC, short-term w_noise ~0.02, out_noise ~0.02 (all substrate-dependent).

**Cost.** ~Tier 1 (quantization is cheap); still Monte Carlo over stochastic parts.

**Limitations.** Still assumes independence across devices/time; no drift; converter
model is uniform-quantizer idealization.

Links: aihwkit hwa_training config (DAC/ADC/w_noise/out_noise fields):
https://github.com/IBM/aihwkit/blob/master/docs/source/hwa_training.rst

## Tier 3 — Composite phenomenological device model (calibrated)

**Concept.** The "realistic but cheap" industry standard (IBM aihwkit). Superimpose
separately-calibrated components instead of one Gaussian:
(a) programming noise (static, magnitude-dependent),
(b) read noise (dynamic; PCM shows 1/f + RTN; sigma grows ~sqrt(log t)),
(c) temporal drift (conductance decays as a power law in time),
plus converter quantization from Tier 2. Calibration alone cannot fix accuracy
because programming noise is stochastic and read-noise/drift are temporal — so all
three must be modeled, not just a static offset.

**Implementation recipe.**
You may use aihwkit, if not available, please install. If the usage of this library brings issues with the compilation, consider reimplementing the noise model manually or consider realizing rewrites in hte aihwkit framework to make it Torch-Compile compatible; therefore, a pip install -e can be desirable.
Requires implementation to PyTorch; don't use NumPy. 

```python
from aihwkit.simulator.configs import InferenceRPUConfig
from aihwkit.simulator.configs.utils import WeightNoiseType
from aihwkit.inference import PCMLikeNoiseModel, GlobalDriftCompensation
from aihwkit.nn.conversion import convert_to_analog

rpu = InferenceRPUConfig()
rpu.forward.inp_res = 1/64.          # ~6-bit DAC
rpu.forward.out_res = 1/256.         # ~8-bit ADC
rpu.forward.w_noise_type = WeightNoiseType.ADDITIVE_CONSTANT
rpu.forward.w_noise  = 0.02
rpu.forward.out_noise = 0.02
rpu.noise_model = PCMLikeNoiseModel(g_max=25.0)   # programming+read+drift, PCM-calibrated
rpu.drift_compensation = GlobalDriftCompensation()

analog = convert_to_analog(model, rpu)
analog.eval()
t_inference = 3600.                  # seconds after programming
analog.program_analog_weights()      # sample programming noise (once)
analog.drift_analog_weights(t_inference)  # apply drift+read noise to that time point
# then run the test set; repeat over instances/times for a distribution
```
Structure of the model: programming noise + drift are applied ONCE per instance
(long-term), then held; per-MACC read/short-term noise varies each tile use
(`rpu.forward`). Evaluate at several `t_inference` and several instances.
If aihwkit is unavailable, reimplement the three terms manually:
`g = g_target + N(0, sigma_prog(g_target)); g *= (t/t0)**(-nu); g += read_noise(g,t)`.
`ReRamCMONoiseModel`/`ReRamWan2022NoiseModel` are alternative device calibrations.

**Calibration defaults.** PCM read-noise sigma ~ g_drift * Q_s * sqrt(log((t+t_read)/(2 t_read))),
t_read=250 ns; programming noise fit as a polynomial in g_target; drift as power law.
CMO/ReRAM programming noise is ~linear in g_target with two acceptance ranges (0.2%, 2%).

**Cost.** Moderate: instances x time-points x test set. Far below SPICE.

**Limitations.** Calibrated to specific memristive devices (PCM/ReRAM), Not to an
oscillator substrate. Use its structure (separate static/temporal/quantization
terms) but recalibrate coefficients to our ONN.

Links: PCM statistical model (equations): https://aihwkit.readthedocs.io/en/latest/pcm_inference.html ;
ReRAM CMO model: https://aihwkit.readthedocs.io/en/latest/reram_inference.html ;
noise API: https://aihwkit.readthedocs.io/en/latest/api/aihwkit.inference.noise.pcm.html ;
repo: https://github.com/IBM/aihwkit ; Rasch et al. doi:10.1038/s41467-023-40770-4

## Tier 4 — Physically-parameterized / stochastic-dynamical model

**Concept.** Derive noise from device physics or a stochastic dynamical model
rather than assuming it. Two flavors:
(a) compact-model random walks (C2C/D2D as Gaussian dispersion PLUS explicit
    dynamic terms: RTN, post-programming relaxation) — the state of the art for
    memristors; and
(b) stochastic differential equations for dynamical substrates: model the device
    trajectory with a learned/deterministic drift term and a stochastic diffusion
    term. This is the most faithful yet still-simulable option for oscillators,
    where computation IS the settling dynamics. Neural-ODE-only twins fail to flag
    noisy regions; adding the SDE noise term is what makes transfer robust.

**Implementation recipe (SDE twin, phase-reduced ONN).**
Requires implementation to PyTorch; don't use NumPy. 

```python
# dphi_i = [omega_i + dOmega_i + sum_j K_ij H(phi_j - phi_i)] dt
#          + b_i dW_i + b_common dW_common      (per-node + shared diffusion)
def em_step(phi, omega, dOmega, K, H, b, b_com, dt, rng):
    drift = omega + dOmega + (K * H(phi[None,:]-phi[:,None])).sum(1)
    dW      = rng.standard_normal(phi.shape) * np.sqrt(dt)
    dW_com  = rng.standard_normal()          * np.sqrt(dt)
    return phi + drift*dt + b*dW + b_com*dW_com     # Euler-Maruyama
```
If you receive a request for correction, you can first check the timestep for convergence (halve dt until statistics stabilize). For
colored (1/f-like) noise add an Ornstein-Uhlenbeck auxiliary state instead of
white dW. If amplitude transients matter, use phase-amplitude/circuit state, not
phase-only. Data-driven option (NADO): fit two small NNs — one deterministic drift,
one stochastic diffusion — from device traces, integrate with an ODE/SDE solver;
sample initial conditions from the empirically measured distribution.

**Calibration defaults.** Fit drift term to mean trajectories; fit diffusion term
to trace-to-trace variance and its power spectral density (to capture colored
noise). Sample initial phase from measured reset distribution.

**Cost.** High: integrate the SDE over many timesteps x trajectories x test set.
Reserve for near-Pareto candidates or final validation.

**Limitations.** Needs device characterization data or a trusted physics model;
solver cost and stiffness; risk of overfitting the twin.

Links: NADO / Neural-SDE twins, https://arxiv.org/abs/2401.07387
(Nat. Commun. 2025, doi:10.1038/s41467-025-64232-1) ;
memristor compact/dynamic terms (RTN + relaxation) survey context in aihwkit docs above.

## Tier 5 — Cycle-accurate SPICE / full circuit reference

**Concept.** Solve the actual circuit with device compact models, peripheral
transistors, parasitics, PVT corners, supply and thermal noise. Ground truth.

**Implementation recipe.** Export the netlist with fitted device compact models
(e.g. VO2/relaxation-oscillator models for an ONN; JART/VTEAM for memristors),
run transient + Monte Carlo (process/mismatch) analyses at chosen corners, extract
the observable (phase/readout), and use these runs to fit the cheaper tiers'
coefficients (programming sigma, read-noise PSD, freq-mismatch spread).

**Calibration defaults.** Use foundry PDK mismatch/corner data if available.

**Cost.** Very high and may not be requested, so you can mainly ignore this tier 
and feel surprised if you ever receive the request to implement this. 

**Limitations.** Slow; may still miss layout/thermal cross-effects; not
differentiable.

Links: general context in Momeni review (cost of fine discretization),
https://arxiv.org/abs/2406.03372

## ONN-specific noise channels (apply ON TOP of the chosen tier)

Generic weight-noise is a starting point, but ONNs encode information in the **phase**
of coupled oscillators (e.g. 0 deg = "0", 180 deg = "1"), so the dominant channels
differ. When the session targets an ONN, add the relevant channel(s):

1. **Oscillator frequency / natural-frequency mismatch `dOmega_i`.** First-order
   term. Hardware ONNs are inherently subject to frequency mismatch and device
   variability; SKONN mitigates it via transistor matching + calibration. Model as
   per-oscillator static offset (Tier-0 style) drawn from a measured spread; note
   there is a frequency-variation threshold beyond which naive computing fails.
2. **Phase / timing jitter (phase diffusion).** Dynamic; corrupts readout directly.
   Model as per-cycle phase noise (Tier-1 style on phase) or as diffusion in the
   SDE (Tier 4). Distinguish common-mode vs independent phase noise.
3. **Coupling / synaptic variation `dK[i,j]`.** The ONN analogue of the per-weight
   delta (e.g. capacitor-bank / resistor mismatch). Apply Tier 0/1 to `K`.
4. **Phase-readout precision / quantization.** Often DOMINANT. A HORN (oscillatory
   RNN) analog transfer using the digital readout got only ~28% agreement with the
   digital model due to analog-vs-float precision; retraining a linear readout on
   analog-generated data recovered digital-twin performance. Lesson: model readout
   quantization (Tier 2) explicitly, and prefer retraining the readout over
   chasing exact noise fidelity.
5. **Amplitude-to-phase conversion, settling-window variation, synchronization
   slips, SHIL binarization, initial-condition/reset variation.** Include when the
   observable depends on transient dynamics.

ONN mitigations seen in the literature: sub-harmonic injection locking (SHIL) to
binarize phase and boost variability robustness; per-oscillator frequency tuning /
calibration; mixed-signal digital propagation of phase for noise immunity.

Links: SKONN (mixed-signal ONN, hardware noise study, freq mismatch),
doi:10.1088/2634-4386/ace9f5 ; multifrequency ONN & mismatch threshold,
doi:10.1002/aidi.202500152 ; HORN analog readout transfer, https://arxiv.org/abs/2509.04064 ;
VO2 SHIL robustness, PMC8085264 ; neuromorphic coupled-oscillator freq tuning,
doi:10.1038/s41598-021-97314-3

## Quality rules

- Separate fabrication mismatch, programming error, read noise, and drift.
- Always state the perturbation redraw timescale and correlation assumptions.
- Distinguish parameter noise from state/process noise.
- Never claim waveform-MSE match implies task-accuracy match.
- For ONNs, always include at least one phase/frequency channel and readout
  quantization; do not model an ONN as a pure MVM weight-noise problem.
- Prefer measured empirical distributions when available; keep simple baselines
  for sensitivity analysis and debugging.
