# Physical Neural Network Hardware-Noise Modeling

## Purpose

Use this skill when a user needs to translate a software-trained neural network
onto analog or physical hardware and must model the effect of nonidealities on
inference accuracy without always running transistor-level or full-physics
simulation.

The skill must distinguish:

- **Static mismatch:** fixed after fabrication, programming, or deployment.
- **Run-to-run variation:** changes when the device is reprogrammed or restarted.
- **Dynamic noise:** changes during an inference trajectory or read operation.
- **Drift/aging:** evolves over minutes, hours, cycles, temperature, or device age.
- **Interface errors:** quantization, clipping, saturation, offsets, and readout errors.
- **Model-form error:** discrepancy between the digital twin and physical dynamics.

## Required Inputs

Ask for missing information only when it materially changes the analysis:

1. Physical substrate and oscillator type.
2. State variables used by the simulation: voltage, amplitude, phase, frequency,
   spikes, conductance, etc.
3. Trainable/deployed parameters: coupling coefficients, oscillator frequencies,
   biases, initial conditions, readout weights, and thresholds.
4. Inference observable and readout method.
5. Available hardware measurements, SPICE data, or process-corner data.
6. Simulation budget and acceptable accuracy uncertainty.
7. Whether robustness evaluation, hardware-aware fine-tuning, or both are required.

## Literature-Query Procedure

1. Begin with Momeni et al., **Training of Physical Neural Networks**, and follow
   references concerning digital twins, physics-aware training, in-situ training,
   model mismatch, and physical perturbations.
2. Search primary literature for the specific substrate plus these terms:
   `noise`, `variation`, `mismatch`, `phase noise`, `jitter`, `frequency spread`,
   `programming error`, `read noise`, `drift`, `quantization`, `hardware-aware
   training`, `stochastic differential equation`, and `compact model`.
3. Prefer papers containing measured device distributions, explicit equations,
   ablation studies, or released simulators/code.
4. For each paper extract:
   - physical system and task;
   - noise source and physical origin;
   - mathematical model and distribution;
   - whether the error is static or dynamic;
   - correlation structure;
   - parameter/state dependence;
   - calibration data;
   - numerical integration or simulation method;
   - inference-accuracy effect;
   - mitigation/training method;
   - estimated simulation cost.
5. Do not treat all perturbations as interchangeable Gaussian noise. Explicitly
   report when a Gaussian approximation is only a baseline.

## Fidelity Ladder

Construct and compare at least the following levels.

### L0 — Fixed deterministic perturbation

Use one sampled or deliberately swept perturbation per physical instance:

`theta_hw = theta + delta_theta`

For deployed coupling weights:

`K_hw[i,j] = K[i,j] + delta_K[i,j]`

Test absolute, relative, biased, and spatially correlated perturbations. Keep the
same perturbation for every example and timestep. This represents fabrication or
programming mismatch, not temporal noise.

Recommended sweep:

`delta_K[i,j] = sigma_abs * z[i,j]`

or

`delta_K[i,j] = sigma_rel * scale(K[i,j]) * z[i,j]`, where `z ~ N(0,1)`.

Include bounded uniform and empirical distributions when appropriate.

### L1 — Independent stochastic parameter noise

Use:

`theta_tilde = theta + epsilon`

with `epsilon` redrawn at a declared timescale: deployment, batch, sample,
oscillation cycle, integration step, or read operation. Compare additive and
multiplicative models. Never omit the resampling timescale from the report.

### L2 — Functional block and interface model

Add nonidealities at their physical location:

- parameter/coupling programming error;
- oscillator natural-frequency mismatch;
- phase and timing jitter;
- amplitude noise;
- input DAC quantization and clipping;
- output/readout noise;
- ADC or phase-detector quantization;
- offsets, gain error, saturation, and nonlinear transfer functions.

Prefer the generic decomposition:

`y_hw = Q_out(F_hw(Q_in(x), theta_hw) + epsilon_out)`.

### L3 — Correlated, state-dependent, and drifting noise

Model shared supply/temperature noise, spatial process gradients, crosstalk,
1/f noise, random telegraph noise, and aging. Useful forms include:

`epsilon = epsilon_global + epsilon_group + epsilon_local`

and

`theta(t) = theta(t0) * (t/t0)^(-nu)`

when power-law drift is physically justified.

Estimate or sweep spatial, temporal, and inter-parameter covariance rather than
assuming independence.

### L4 — Stochastic dynamical model

For phase-reduced coupled oscillators, start with:

`dphi_i = [omega_i + Delta_omega_i + sum_j K_ij H(phi_j-phi_i)] dt
          + b_i(phi, t) dW_i + b_common(phi, t) dW_common`

Use Euler–Maruyama only after checking the required timestep and convergence.
When amplitude transients matter, use a phase-amplitude or circuit-state model
instead of phase-only dynamics. Colored noise may be represented with an
auxiliary Ornstein–Uhlenbeck state or a learned Neural-SDE digital twin.

### L5 — Compact-device, circuit, or SPICE reference

Include transistor/device compact models, parasitics, PVT corners, supply noise,
thermal noise, and peripheral circuits. Use this level selectively to calibrate
or validate lower-cost models; do not make it the default inner-loop simulator.

## Oscillatory-Neural-Network Checklist

Always consider whether inference is sensitive to:

1. Natural-frequency mismatch `Delta_omega_i`.
2. Coupling magnitude, sign, delay, and asymmetry errors.
3. Phase diffusion and cycle-to-cycle jitter.
4. Common-mode versus independent phase noise.
5. Amplitude-to-phase conversion.
6. Initial-condition and reset variation.
7. Settling-time or observation-window variation.
8. Synchronization slips and attractor switching.
9. Sampling-clock or phase-detector error.
10. Readout precision, quantization, and threshold offsets.
11. Temperature, supply, and process corners.
12. Differences between simulated and silicon transfer functions.

## Experimental Design

Use nested sampling so distinct uncertainty sources are not conflated:

```text
for hardware_instance in 1..N_static:
    sample static mismatch, process parameters, and programming errors
    for noise_trace in 1..N_dynamic:
        sample temporal/read noise trajectory
        evaluate the full test set or a statistically justified subset
```

Report:

- mean accuracy and confidence interval;
- standard deviation and lower-tail accuracy;
- worst observed or selected percentile accuracy;
- disagreement with the ideal model;
- calibration error where relevant;
- latency/settling failures;
- simulation time and memory cost;
- ranking stability of candidate designs across fidelity levels.

Use common random numbers when comparing designs to reduce Monte Carlo variance.
Increase sample counts near decision boundaries rather than uniformly.

## Multi-Fidelity Agentic Loop

Recommended policy:

1. Screen many candidates with L0.
2. Re-evaluate survivors with L1–L2.
3. Use L3–L4 for candidates near the Pareto frontier or with unstable rankings.
4. Use L5 only for calibration points and final validation.
5. Fit a discrepancy or surrogate model between adjacent levels.
6. Promote a candidate when expected decision value exceeds added simulation cost.
7. Periodically test whether the low-fidelity model preserves the candidate ranking,
   not merely whether it minimizes waveform error.

A useful promotion score is:

`score = probability_of_ranking_change * consequence / added_simulation_cost`.

## Calibration Strategy

1. Collect repeated traces from multiple physical devices and operating conditions.
2. Separate between-device variance from within-device temporal variance.
3. Fit distributions conditional on state, parameter magnitude, time, temperature,
   and supply when data supports it.
4. Compare simulated and measured summary statistics: frequency distribution,
   phase-noise spectrum, autocorrelation, cross-correlation, synchronization time,
   phase-slip rate, output margins, and task accuracy.
5. Validate on held-out devices and operating conditions.
6. Prefer the simplest model that preserves decisions and relevant failure modes.

## Required Output

Return:

1. A short system-specific interpretation.
2. A table with columns:
   `level`, `noise source`, `equation/distribution`, `static/dynamic`,
   `calibration data`, `cost`, `failure modes captured`, and `limitations`.
3. A recommended minimum viable model.
4. A high-fidelity reference model.
5. A staged simulation and calibration plan.
6. A compact pseudocode or implementation sketch.
7. Key primary references with stable DOI, publisher, or arXiv links.
8. Explicit assumptions and unresolved questions.

## Quality Rules

- Separate fabrication mismatch, programming error, read noise, and drift.
- State the perturbation redraw timescale and correlation assumptions.
- Distinguish parameter noise from state/process noise.
- Do not claim that matching waveform MSE guarantees matching task accuracy.
- Include at least one ONN-specific phase/frequency model when oscillators are used.
- Include uncertainty bars rather than a single noisy-accuracy number.
- Use measured empirical distributions when available, but retain simple baselines
  for sensitivity analysis and debugging.
- Recommend hardware-aware fine-tuning only after identifying which modeled
  nonidealities are differentiable or can be handled through sampling/surrogates.
