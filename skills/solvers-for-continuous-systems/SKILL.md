## 2. Solver problem statement

A physical neural network may appear in one of these forms:

### Explicit ODE

```text
dx/dt = f(t, x, u, theta)
x(t0) = x0
```

Typical for phase-reduced or behavioral oscillator models.

### Stochastic differential equation

```text
dx = f(t, x, u, theta) dt + G(t, x, theta) dW
```

Typical when phase diffusion, thermal noise, or state-dependent device noise is
modeled dynamically.

### Differential-algebraic equation

```text
F(t, y, dy/dt, u, theta) = 0
```

Typical for transistor/circuit simulation after modified nodal analysis. Circuit
models should not be forced into an explicit ODE if the natural formulation is a
DAE.

### Discrete recurrence

```text
x[n+1] = Phi_n(x[n])
```

Obtained after choosing a time integrator. This form is central to parallel scan,
DEER, Parareal, MGRIT, and fixed-point approaches.

### Periodic steady-state problem

```text
x(t + P) = x(t)
```

Used when only the settled oscillation is needed. Shooting and harmonic balance can
avoid simulating a long startup transient.

## 3. Shared vocabulary

- **Physical/model fidelity**: how closely the equations represent the device.
  Solver accuracy is separate: a very accurate solver can still solve the wrong
  model.
- **Local/global error**: one-step truncation error versus accumulated trajectory
  error.
- **Phase error**: timing displacement of an oscillator. Small state error can
  accumulate into large phase error over many periods.
- **Stiffness**: fast stable modes force explicit methods to use a very small step
  for stability, even when the desired observable varies slowly.
- **A-stability/L-stability**: stability properties important for stiff decaying
  modes. Backward Euler is L-stable; trapezoidal is A-stable but may ring on very
  stiff modes.
- **Consistent DAE initialization**: initial `y0` and `ydot0` must satisfy the
  algebraic constraints.
- **Batch parallelism**: integrate independent inputs, devices, or Monte Carlo
  traces simultaneously. Exploit this before AOT compilation time.
- **Time parallelism**: reduce sequential dependence along the time axis.
- **Work**: total operations. **Span/depth**: critical-path operations with enough
  processors. An algorithm can have O(T) work and O(log T) span.
- **Predictability**: sensitivity of future states to small perturbations. Poorly
  predictable or chaotic dynamics make global parallel-in-time root solves badly
  conditioned.
- **Numerical damping/dispersion**: artificial amplitude decay or phase-speed error
  introduced by the solver.

Gander groups classical parallel-in-time methods into four historical families:
multiple shooting, domain decomposition/waveform relaxation, space-time multigrid,
and direct time-parallel methods. Time parallelism is most useful after spatial or
batch parallelism has saturated.

Primary survey:
https://www.unige.ch/~gander/Preprints/50YearsTimeParallel.pdf
DOI: https://doi.org/10.1007/978-3-319-23321-5_3

# TIER 0 — Fixed-step explicit transient integration

## Concept

March forward sequentially using Euler, midpoint/Heun, or RK4. The method is simple,
transparent, and easy to batch on MPS/NVIDIA GPU. RK4 is the preferred Tier-0 baseline.

## Suitable model

Non-stiff ODEs such as phase-reduced coupled oscillators:

```text
dphi_i/dt = omega_i + sum_j K_ij H(phi_j - phi_i)
```

## Minimal implementation
Requires implementation to PyTorch; don't use NumPy. 


```python
import numpy as np

def rk4(rhs, x0, t0, dt, n_steps, args=()):
    x = np.asarray(x0)
    t = t0
    output = [x.copy()]
    for _ in range(n_steps):
        k1 = rhs(t, x, *args)
        k2 = rhs(t + dt/2, x + dt*k1/2, *args)
        k3 = rhs(t + dt/2, x + dt*k2/2, *args)
        k4 = rhs(t + dt,   x + dt*k3,   *args)
        x = x + dt*(k1 + 2*k2 + 2*k3 + k4)/6
        t = t + dt
        output.append(x.copy())
    return np.stack(output)
```

Vectorize `x` as `(batch, state)` and preserve the batch dimension inside `rhs`.

## Starting settings

- RK4.
- Initially try 20-40 steps per fastest physical oscillation period.
- Run with `dt`, `dt/2`, and `dt/4`; accept only after the task metric and phase
  relations have converged.
- Save only readout times unless full trajectories are required.

## Captures

Full transient of the chosen ODE, including startup and attractor selection.

## Cost

Sequential span O(N_steps); RK4 uses four right-hand-side evaluations per step.
Batch parallelism is excellent.

## Failure modes & debugging suggestions
In case you are requested to make a correction of your implementation during a debug/correction session, consider these failure modes to steer your debugging efforts.

- Explicit stability restriction on stiff systems.
- Long-horizon phase drift despite acceptable pointwise amplitude error.
- Aliasing if the fastest oscillator is undersampled.
- Large memory use if all states are saved.

Hint:
The solver may pass if halving `dt` changes neither ONN label nor relevant phase
margin beyond the stated tolerance.

## Practical links

- Diffrax fixed-step solvers and `jax.lax.scan` ecosystem:
  https://docs.kidger.site/diffrax/
- Standard numerical reference: Hairer, Nørsett, Wanner, *Solving Ordinary
  Differential Equations I*.

# TIER 1 — Adaptive explicit integration and event-driven stopping

## Concept

Use an embedded Runge-Kutta pair to estimate local error and adapt the step size.
Stop when the network reaches a task-relevant event rather than integrating every
sample to a fixed worst-case horizon.

## Suitable model

Non-stiff ODEs with varying activity or uncertain settling time.

## Minimal implementation

Requires implementation to PyTorch; don't use NumPy. 
```python
from scipy.integrate import solve_ivp

sol = solve_ivp(
    fun=rhs,
    t_span=(t0, tmax),
    y0=x0,
    method="DOP853",          # RK45 is cheaper; DOP853 is useful for references
    rtol=1e-7,
    atol=1e-10,
    events=settling_event,
    dense_output=False,
)
x_final = sol.y[:, -1]
```

Example settling event:

```python
def settling_event(t, x):
    return locking_residual(x) - lock_tolerance
settling_event.terminal = True
settling_event.direction = -1
```

## Starting settings

- `Tsit5` or `RK45` for general non-stiff work.
- `DOP853` for a high-accuracy non-stiff reference.
- `rtol=1e-6`, `atol=1e-9`, then tighten once.
- Bound `max_step` by a fraction of the fastest oscillation period even with
  adaptivity; local-error control alone may not protect a phase-sensitive readout.

## Cost

Sequential in accepted steps, but avoids unnecessary fine steps and avoids long
post-settling integration. GPU batching is possible, although trajectories with
very different adaptive grids may reduce efficiency.

## Failure modes & debugging suggestions
In case you are requested to make a correction of your implementation during a debug/correction session, consider these failure modes to steer your debugging efforts.

- Step count explodes on stiffness.
- Different trajectories take different numbers of steps, causing GPU divergence.
- A naive event may trigger on a temporary near-lock; require persistence over a
  time window or hysteresis.
Hint:
Tighten tolerances by 10x and verify the label, locking time, and circular phase
error are stable.

## Practical links

- Diffrax solver choice: https://docs.kidger.site/diffrax/usage/how-to-choose-a-solver/
- Diffrax API: https://docs.kidger.site/diffrax/api/diffeqsolve/
- SciPy `solve_ivp`: https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html

# TIER 2 — Implicit stiff ODE and circuit-DAE integration

## Concept

Use backward Euler, trapezoidal, BDF, Radau, or IMEX methods. Each implicit step
requires a nonlinear solve, normally Newton or inexact Newton-Krylov. The method
costs more per step but permits much larger stable steps on stiff systems.

At circuit fidelity, modified nodal analysis naturally gives:

```text
F(t, y, ydot) = 0
```

SPICE-like simulators solve nonlinear DAEs rather than ordinary explicit ODEs.
Backward Euler and trapezoidal formulas are A-stable; classic circuit simulators
also use Gear/BDF formulas.

## Suitable model

- Transistor/compact-device circuit models.
- Relaxation oscillators with sharp switching.
- Fast carrier plus slow phase-locking or bias dynamics.
- Strong couplings producing widely separated Jacobian eigenvalues.

## Minimal implicit-step implementation

Backward Euler solves:

```text
g(z) = z - x_n - dt f(t_{n+1}, z) = 0
```

Required implementation to PyTorch; don't use NumPy. 

```python
import numpy as np

def backward_euler_step(rhs, jac_rhs, x_n, t_next, dt,
                        tol=1e-9, max_newton=20):
    z = x_n.copy()
    I = np.eye(x_n.size)
    for _ in range(max_newton):
        residual = z - x_n - dt*rhs(t_next, z)
        if np.linalg.norm(residual, ord=np.inf) < tol:
            return z, True
        J = I - dt*jac_rhs(t_next, z)
        dz = np.linalg.solve(J, -residual)
        z = z + dz
    return z, False
```


## Practical production paths

### ODE only

```python
solve_ivp(rhs, (t0, tf), x0, method="Radau", jac=jac,
          rtol=1e-6, atol=1e-9)
# or method="BDF" / "LSODA"
```

## Cost

Sequential span O(N_steps). Each step includes nonlinear iterations and sparse
linear solves. Often faster than explicit methods when stiffness controls the step.

## Failure modes & debugging suggestions

- Inconsistent DAE initial conditions.
- Singular or ill-conditioned Jacobian.
- Trapezoidal ringing on very stiff switching modes.
- Newton failure after discontinuities; add breakpoints, damping, or step rejection.
- Treating a high-index DAE as index 1 without index reduction.

# TIER 3 — Decomposition and waveform-relaxation solvers

## Concept

Partition the network into oscillators or subcircuits. During one iteration, solve
each subsystem over a complete time window while holding coupling waveforms from the
previous iteration. Exchange updated waveforms and repeat.

This is naturally parallel across subsystems and can reuse specialized local
solvers. It is the circuit-simulation branch of domain decomposition. The implicit-
language-model paper is conceptually related: simultaneous fixed-point iterations
trade a small number of global iterations for sequence-level parallelism, and exact
convergence may not always be necessary for a task metric. For a physical simulator,
however, approximation must be validated explicitly.

## Minimal Jacobi waveform-relaxation recipe

For subsystems:

```text
dx_i/dt = f_i(x_i, coupling_i(x_1,...,x_m))
```

```python
waveforms = initial_waveform_guess()
for iteration in range(max_iter):
    new_waveforms = parallel_map(
        lambda i: solve_local_subsystem(
            i, coupling_from=waveforms, time_window=window),
        subsystem_ids,
    )
    residual = waveform_norm(new_waveforms - waveforms)
    waveforms = relaxation*new_waveforms + (1-relaxation)*waveforms
    if residual < tolerance:
        break
```

Jacobi WR updates all blocks in parallel. Gauss-Seidel WR uses new waveforms as soon
as available and may converge faster but exposes less parallelism. Split long time
ranges into windows; warm-start each window from the preceding one.

## Advantages

- Coupling graph is sparse or weakly coupled.
- Each oscillator/subcircuit has a costly internal model but low-dimensional ports.
- Different blocks need different integrators or time steps.
- Co-simulation is required.

## Cost

`number_of_WR_iterations × cost_of_slowest_subsystem_window`, with subsystem-level
parallelism. Communication is whole waveforms rather than per-time-step states.

## Failure modes & debugging suggestions

- Strong/instantaneous coupling causes slow or divergent iteration.
- Long windows worsen contraction.
- Discontinuous coupling waveforms need careful interpolation.
- A task-accurate approximate fixed point is not automatically waveform accurate.

## Stabilization

Shorter windows, under-relaxation, optimized transmission/interface conditions,
overlap, coarse models, or Newton/Krylov acceleration.

# TIER 4 — Parallel-in-time solvers

Tier 4 attacks the sequential time axis directly. Implement one branch: **4A
coarse/fine PinT**, **4B Newton+scan**, or **4C probabilistic PinT**.

Before implementing Tier 4:

1. Check predictability: perturb the initial state and measure growth, or estimate a
   finite-time/largest Lyapunov exponent. Chaotic/unpredictable trajectories make
   global parallel solves poorly conditioned.
2. For oscillators, compare coarse and fine PHASE propagation, not only amplitude.

## TIER 4A — Parareal and multigrid-reduction-in-time

### Concept

Split time into windows. A cheap coarse propagator `G` predicts sequentially; an
accurate fine propagator `F` runs across windows in parallel. Parareal iterates:

```text
U_{n+1}^{k+1} = G(U_n^{k+1}) + F(U_n^k) - G(U_n^k)
```

MGRIT generalizes the idea to multiple time grids and is non-intrusive around an
existing one-step propagator.

### Minimal Parareal skeleton

```python
def parareal(F, G, x0, windows, max_iter, tol):
    U = coarse_sequential_rollout(G, x0, windows)
    for k in range(max_iter):
        fine = parallel_map(lambda n: F(U[n], windows[n]), range(len(windows)))
        U_new = [x0]
        for n in range(len(windows)):
            correction = fine[n] - G(U[n], windows[n])
            U_new.append(G(U_new[n], windows[n]) + correction)
        if interface_residual(U_new, U) < tol:
            return U_new, True
        U = U_new
    return U, False
```

### Use when

You need a non-intrusive wrapper or
have distributed or multi-device resources.

### Critical ONN warning

Standard Parareal can converge slowly or become unstable for hyperbolic/highly
oscillatory problems because coarse/fine phase error accumulates. Use a phase-aligned
or averaged coarse propagator, a phase-reduced coarse model, or MGRIT tailored to
the oscillatory spectrum.

### Practical implementation

- Prototype with PyMGRIT.
- Use XBraid for a mature non-intrusive MGRIT implementation.
- Fine propagator: trusted Tier 1/2.
- Coarse propagator: phase-reduced Tier 3A, large-step implicit method, or averaged
  envelope model — not simply a badly underresolved explicit step.

## TIER 4B — Global Newton solve plus associative prefix scan

### Concept

Following Iacob et al. and DEER, stack all time states into one vector and solve the
discretized dynamics as a nonlinear root problem:

```text
h_k(x_1,...,x_N) = x_k - Phi_{k-1}(x_{k-1}) = 0
```

The Newton Jacobian is block lower-bidiagonal. The Newton correction satisfies an
affine recurrence:

```text
delta_x_k = A_k delta_x_{k-1} + b_k
```

Composition of affine maps is associative, so all corrections can be computed with
a parallel prefix scan. With enough processors, each Newton iteration has
logarithmic span in the number of time points. Iacob et al. derive explicit and
implicit ODE variants and prove local quadratic Newton convergence under standard
smoothness/invertibility assumptions.

### From-scratch scan object

Represent an affine map as `(A, b)` with `z_out = A z_in + b`. Compose:

```python
def compose(right, left):
    # right(left(z)); associative
    A2, b2 = right
    A1, b1 = left
    return A2 @ A1, A2 @ b1 + b2
```

### Initialization

A good initial trajectory is central. Use, in order of preference:

1. previous nearby inference/parameter solution;
2. coarse phase/envelope rollout;
3. interpolated checkpoints from a short sequential solve;
4. constant `x0` or zeros only as a baseline.

### Stabilized variants

- **Quasi-DEER**: diagonal/block-diagonal Jacobian approximation; lower memory and
  avoids cubic state-size scaling.
- **ELK**: Levenberg-Marquardt stabilization evaluated through parallel Kalman
  smoothing.
- **Quasi-ELK**: practical stabilized low-complexity option.

### Use when

The time grid is long, the state is moderate, a GPU is available, and dynamics
are predictable/synchronizing enough for few global iterations.

### Failure modes & debugging suggestions

- Chaotic/unpredictable dynamics: conditioning worsens rapidly with horizon.
- Large dense per-time Jacobians: O(N d^2) memory and costly d×d algebra.
- Newton leaves its convergence basin: residual spikes or NaNs.
- GPU launch/scan overhead dominates short sequences.
- Parallel method converges to the discretized trajectory; it does not improve the
  underlying integrator's truncation error.

## TIER 4C — Parallel-in-time probabilistic numerical ODE solver

### Concept

Treat the numerical ODE solution as Bayesian state estimation. A time-parallel
iterated extended Kalman smoother processes all time points in parallel and returns
a posterior over the numerical solution, including numerical-approximation
uncertainty. Reported span drops from linear to logarithmic in the number of time
steps.

### Use when

Numerical uncertainty must be distinguished from hardware noise/model uncertainty,
or adaptive confidence in the solver output is valuable to the agentic decision.

### Cost and limitation

More machinery and constants than deterministic solvers. Do not use merely for a
point estimate unless uncertainty changes decisions.

- JMLR version: https://www.jmlr.org/papers/v25/23-1261.html
- Code: https://github.com/nathanaelbosch/parallel-in-time-ode-filters

## TIER 5. Cross-cutting modifier — SDE integration for hardware noise

When dynamic noise is represented by an SDE, solver selection must respect whether
the model is Itô or Stratonovich, whether noise is additive, and whether diffusion
fields commute.

### Minimal baseline

Euler-Maruyama for an Itô SDE:

```python
x = x + f(t, x)*dt + G(t, x) @ (sqrt(dt)*normal())
```

Use only as a baseline. For convergence studies, compare paths using the **same
underlying Brownian realization**, not unrelated random draws.

## Notes on Cross-cutting modifier — differentiability and gradients

If the outer agentic loop uses gradients:

- Differentiate through fixed-step solvers directly for short trajectories.
- Use checkpointing or adjoint methods for long trajectories.
- Verify gradients by finite differences on a small problem.
- Near bifurcations, phase slips, threshold readouts, and attractor changes,
  gradients may be ill-conditioned or undefined even if the solver is correct.
- An adjoint saves memory but may produce inaccurate gradients if the backward solve
  does not reconstruct the forward trajectory accurately. Tighten and test.
- Parallel Newton/DEER can parallelize forward evaluation and its linearized solves,
  but still requires convergence and stable Jacobian approximations.

## Quality rules

- Do not confuse better equations with a better solver.
- Do not use a solver without identifying ODE/SDE/DAE structure first.
- Do not use raw phase subtraction across a 2π wrap.
- Do not use standard Parareal on an oscillator without checking coarse/fine phase
  mismatch.
- Do not use global Newton/scan without reporting convergence and conditioning.
- Do not claim logarithmic span implies logarithmic total work.
- Do not use unrelated Brownian paths to compare SDE discretizations.
- Do not accept a periodic steady state if startup/attractor selection affects
  inference.
- Keep numerical error below the hardware/model-error floor unless a documented
  task-aware approximation justifies otherwise.
